### 3.2 Decoy 策略详细分析

#### 策略 A：高阈值 Decoy 过滤

**配置**：
```
目标词 "你好真真": boost=1.5, threshold=0.3
Decoy "你好": boost=3.0, threshold=0.15
Decoy "你好啊": boost=3.0, threshold=0.15
Decoy "您好": boost=3.0, threshold=0.15
```

**结果**：
| 指标 | 数值 | 评估 |
|------|------|------|
| FRR | 98.61% | ❌ 几乎所有正样本被拒 |
| FAR | 0.74% | ✓ 极好 |
| Decoy 拦截 | 523 | - |

**失败原因**：Transducer 模型在处理 "你好真真" 时，会先匹配到较短的 "你好" 序列，触发 Decoy，导致正样本被误判。

#### 策略 B：延迟决策 + Decoy 组合

**配置**：
- 分块处理：chunk_size=100ms
- 前缀超时：prefix_timeout=600ms
- Decoy 配置同策略 A

**结果**：
| 指标 | 数值 | 评估 |
|------|------|------|
| FRR | 52.78% | ❌ 仍然过高 |
| FAR | 16.11% | ⚠️ 有改善但不达标 |
| Decoy 拦截 | 440 | - |

**分析**：延迟决策能恢复部分正样本（从 98.61% 降到 52.78%），但效果有限。

## 四、根本问题分析

### 4.1 核心矛盾

**"你好真真" 包含 "你好" 作为前缀**

```
目标词: 你好真真 → n ǐ h ǎo zh ēn zh ēn
干扰词: 你好     → n ǐ h ǎo
                  ↑↑↑↑↑↑↑↑
                  完全重叠
```

### 4.2 Transducer 模型特性

1. **序列匹配机制**：Transducer 是序列到序列模型，会逐帧处理音频
2. **前缀优先匹配**：当检测到 "你好" 序列时，模型倾向于立即输出
3. **无法回溯**：一旦输出 "你好"，无法撤回并等待 "真真"

### 4.3 数据层面问题

| 问题 | 说明 |
|------|------|
| 正负样本声学重叠 | "你好" 和 "你好真真" 前半部分完全相同 |
| 预训练偏差 | WenetSpeech 包含大量 "你好"，几乎无 "你好真真" |
| TTS 数据局限 | 合成语音缺乏真人语音的多样性 |

## 七、结论与下一步方向

### 7.1 Decoy 方案结论

| 结论 | 说明 |
|------|------|
| **Decoy 方案不可行** | 无法同时满足 FRR 和 FAR 目标 |
| 根本原因 | Transducer 的前缀匹配机制导致正样本被 Decoy 拦截 |
| 最佳 Decoy 结果 | 策略 B: FRR=52.78%, FAR=16.11%（均不达标） |

### 7.2 推荐下一步方案

#### 方案 A：多阶段检测（推荐）

```
阶段 1: 检测 "你好" 前缀 (使用现有模型)
阶段 2: 验证 "真真" 后缀 (需要新模型/方法)
```

**验证方案选项**：
1. **CNN 分类器**：对后缀音频进行二分类
2. **ASR 验证**：使用语音识别转录后缀，检查是否包含 "真真"
3. **DTW 模板匹配**：与 "真真" 模板进行动态时间规整匹配
4. **MLP 分类器**：基于音频特征的多层感知机分类

#### 方案 B：更换唤醒词

将 "你好真真" 改为不以常见词为前缀的词：
- "真真你好"
- "嗨真真"
- "喂真真"

#### 方案 C：收集真实数据

收集真人语音 "你好真真" 样本进行训练，提高模型区分能力。
