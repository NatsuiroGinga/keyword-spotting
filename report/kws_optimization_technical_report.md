# "你好真真"关键词识别模型优化技术报告

## 摘要

本报告详细记录了"你好真真"中文唤醒词识别(KWS)模型从V1版本到最终多阶段检测方案的完整优化历程。项目采用零样本学习范式，仅使用TTS合成数据进行模型微调，无需真实人声训练数据。

**核心挑战**：目标唤醒词"你好真真"以常见问候语"你好"为前缀，导致模型难以区分两者，产生严重的误唤醒问题。

**优化历程**：
- V1基线方案：FAR=44.07%，未引入负样本
- V2负样本训练：FAR降至34.26%，仍未达标
- V3大规模训练：FAR反升至72.22%，出现过拟合
- Decoy策略：FRR飙升至82.64%，方案失败
- **最终方案**：V3 + MLP验证器，FAR=1.30%，FRR=0%，**成功达标**

**关键成果**：通过多阶段检测架构，将误唤醒率从72.22%降至1.30%（降幅70.93%），同时保持零漏唤醒率，实现了生产级性能指标。

## 1. 问题定义

### 1.1 任务背景

关键词识别(Keyword Spotting, KWS)是智能语音交互的入口技术，用于在连续语音流中检测特定唤醒词。本项目目标是为中文唤醒词"你好真真"构建高精度的离线识别模型。

**项目约束条件**：
- **零样本场景**：无真实人声训练数据，仅使用TTS合成语音
- **离线部署**：模型需在边缘设备运行，无网络依赖
- **实时性要求**：RTF(Real-Time Factor) < 1.0

### 1.2 评估指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| **FRR** (False Rejection Rate) | 漏唤醒率 = FN / (TP + FN) | < 5% |
| **FAR** (False Accept Rate) | 误唤醒率 = FP / (TN + FP) | < 10% |
| **RTF** (Real-Time Factor) | 处理时间 / 音频时长 | < 1.0 |
| **Accuracy** | 整体准确率 | > 95% |
| **F1 Score** | 精确率与召回率的调和平均 | > 95% |

### 1.3 核心挑战

**前缀匹配问题**：目标唤醒词"你好真真"(nǐ hǎo zhēn zhēn)以"你好"(nǐ hǎo)为前缀，两者在声学特征上高度相似。

```
"你好真真": n ǐ h ǎo zh ēn zh ēn  (8个音素)
"你好":     n ǐ h ǎo              (4个音素)
                    ↑
              仅差4个音素
```

**问题根源**：
1. **声学相似性**：前4个音素完全相同，占目标词50%
2. **预训练偏差**：WenetSpeech语料中"你好"出现频率远高于"你好真真"
3. **Transducer特性**：RNN-T模型倾向于在识别到有效序列后立即输出

### 1.4 测试数据集

| 类别 | 数量 | 说明 |
|------|------|------|
| 正样本 | 144 | 8种语音 × 6种信噪比 × 3种韵律变化 |
| 负样本 | 540 | 包含84个"你好"变体（泥豪、李浩等） |
| **合计** | **684** | 完整测试集 |

## 2. 技术方案演进

### 2.1 基础架构

#### 2.1.1 模型架构

采用Zipformer-Transducer架构，基于预训练的WenetSpeech模型进行微调：

```
┌─────────────────────────────────────────────────────────────┐
│                    Zipformer-Transducer                     │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │   Encoder   │───▶│   Joiner    │◀───│   Decoder   │     │
│  │ (Zipformer) │    │  (320 dim)  │    │  (320 dim)  │     │
│  └─────────────┘    └──────┬──────┘    └─────────────┘     │
│        ▲                   │                                │
│        │                   ▼                                │
│   Audio Input         Token Output                          │
│   (Fbank 80)         (Pinyin-based)                        │
└─────────────────────────────────────────────────────────────┘
```

**模型参数**：
| 组件 | 配置 |
|------|------|
| 参数量 | 3.3M (量化后约1M) |
| Encoder层数 | 6层 (每层1个stack) |
| Encoder维度 | 128 |
| Decoder维度 | 320 |
| Joiner维度 | 320 |
| 注意力头数 | 8 |
| 下采样因子 | (2, 4) |

#### 2.1.2 分词策略

采用拼音分词，支持声调标记：

```
"你好真真" → n ǐ h ǎo zh ēn zh ēn
```

关键词配置格式：
```
n ǐ h ǎo zh ēn zh ēn :boost #threshold @你好真真
```

#### 2.1.3 TTS数据生成

使用Edge-TTS生成多样化训练数据：

| 配置项 | 正样本 | 负样本 |
|--------|--------|--------|
| 语音种类 | 全部中文语音 | 5种代表性语音 |
| 语速变化 | ±30% (7档) | ±20% (3档) |
| 音调变化 | ±15Hz (7档) | ±10Hz (3档) |
| 样本数 | 539 | 873 |

### 2.2 V1: 基线方案

#### 2.2.1 方案设计

V1采用最简单的微调策略：仅使用正样本进行训练。

**训练配置**：
```bash
# scripts/run_finetune.sh
--num-epochs 10
--base-lr 0.0005
--max-duration 300
--use-fp16 1
--causal 1
```

#### 2.2.2 实验结果

| 指标 | V1结果 | 目标值 | 差距 |
|------|--------|--------|------|
| FRR | 10.42% | < 5% | +5.42% |
| FAR | 44.07% | < 10% | +34.07% |

#### 2.2.3 问题分析

- **高FAR**：模型未见过负样本，无法学习区分"你好"和"你好真真"
- **高FRR**：训练数据量不足，模型泛化能力有限

### 2.3 V2: 负样本训练

#### 2.3.1 方案设计

引入负样本训练，增强模型的区分能力。

**负样本构成**：
- **硬负样本** (810个)："你好"、"您好"、"你好啊"、"泥豪"、"李浩"等15种
- **通用负样本** (63个)："早上好"、"晚上好"、"播放歌曲"等20种

**训练配置优化**：
```bash
# scripts/run_finetune_v2.sh
--num-epochs 20        # 10 → 20
--base-lr 0.0003       # 0.0005 → 0.0003
--max-duration 500     # 300 → 500
```

#### 2.3.2 实验结果

| 配置 | FRR | FAR | 说明 |
|------|-----|-----|------|
| boost=0.3, threshold=0.6 | 0.00% | 53.70% | 高召回，高误报 |
| boost=0.3, threshold=0.7 | 3.47% | 47.41% | 略有改善 |
| boost=1.0, threshold=0.65 | 12.50% | 34.26% | **最佳平衡** |
| boost=1.5, threshold=0.7 | 29.86% | 20.37% | FAR改善但FRR恶化 |

#### 2.3.3 问题分析

- FAR从44.07%降至34.26%，改善约10%
- FRR与FAR呈强负相关，无法同时优化
- **根本原因**：模型在声学层面仍无法有效区分前缀

---

### 2.4 V3: 大规模训练

#### 2.4.1 方案设计

尝试通过增加训练规模提升模型能力。

**配置变更**：
- 训练轮数：20 → 30
- 样本数量：1412 → 5440
- 数据增强：启用SpecAugment

#### 2.4.2 实验结果

| 指标 | V2最佳 | V3结果 | 变化 |
|------|--------|--------|------|
| FRR | 12.50% | **0.00%** | ↓12.50% |
| FAR | 34.26% | **72.22%** | ↑37.96% |

#### 2.4.3 问题分析

- **FRR大幅改善**：模型对正样本的识别能力显著增强
- **FAR严重恶化**：模型过度拟合"你好"前缀，将所有包含"你好"的音频都识别为唤醒词
- **过拟合现象**：更多训练反而强化了前缀匹配的倾向

## 3. 失败经验分析

### 3.1 Decoy策略失败

#### 3.1.1 方案设计

注册"你好"等短语作为诱饵关键词(Decoy)，期望模型能够区分诱饵词和目标词。

**关键词配置**：
```
n ǐ h ǎo :0.5 #0.3 @你好           # 诱饵词，低boost
n ǐ h ǎo zh ēn zh ēn :1.0 #0.5 @你好真真  # 目标词，高boost
```

#### 3.1.2 实验结果

| 指标 | 预期 | 实际 |
|------|------|------|
| FAR | 显著降低 | 9.63% ✓ |
| FRR | 保持不变 | **82.64%** ✗ |

#### 3.1.3 失败原因分析

```
┌─────────────────────────────────────────────────────────────┐
│                    Transducer解码过程                        │
├─────────────────────────────────────────────────────────────┤
│  输入: "你好真真" 音频                                        │
│                                                             │
│  时间 t=0 ──────────────────────────────────────▶ t=T       │
│       │                                                     │
│       ▼                                                     │
│  解码: n → ǐ → h → ǎo → [匹配"你好"!] → 立即输出            │
│                         ↑                                   │
│                    问题发生点                                │
│                                                             │
│  期望: n → ǐ → h → ǎo → zh → ēn → zh → ēn → [匹配"你好真真"]│
└─────────────────────────────────────────────────────────────┘
```

**核心问题**：Transducer模型采用贪婪解码，当检测到有效关键词序列时立即输出。由于"你好"是"你好真真"的前缀，模型总是先匹配到"你好"。

#### 3.1.4 经验教训

1. **前缀关键词不适合作为Decoy**：短关键词会在长关键词之前被匹配
2. **Transducer的贪婪特性**：无法通过后处理规则解决前缀问题
3. **需要架构级解决方案**：单模型方案无法解决此类问题

---

### 3.2 过拟合问题

#### 3.2.1 现象描述

V3模型在增加训练规模后，FRR从12.50%降至0%，但FAR从34.26%飙升至72.22%。

#### 3.2.2 原因分析

```
┌─────────────────────────────────────────────────────────────┐
│                    过拟合机制分析                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  正样本特征分布:                                             │
│  ┌──────────────────────────────────────────┐               │
│  │  "你好" 特征空间  │  "真真" 特征空间      │               │
│  │  ████████████████│██████████████████████ │               │
│  └──────────────────────────────────────────┘               │
│                                                             │
│  负样本特征分布:                                             │
│  ┌──────────────────┐                                       │
│  │  "你好" 特征空间  │                                       │
│  │  ████████████████│                                       │
│  └──────────────────┘                                       │
│                                                             │
│  过拟合后的决策边界:                                         │
│  ┌──────────────────────────────────────────┐               │
│  │  只要检测到"你好"特征 → 判定为唤醒词      │               │
│  └──────────────────────────────────────────┘               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**结论**：模型学习到了"你好"是唤醒词的强特征，忽略了"真真"后缀的区分作用。

## 4. 最终成功方案：多阶段检测

### 4.1 架构设计

采用两阶段级联架构，分离检测和验证功能：

```
┌─────────────────────────────────────────────────────────────┐
│                    多阶段检测架构                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  输入音频                                                    │
│      │                                                      │
│      ▼                                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  阶段1: Zipformer KWS (V3模型)                       │   │
│  │  - 目标: 高召回率检测"你好真真"候选                   │   │
│  │  - 阈值: 0.3 (宽松)                                  │   │
│  │  - 特点: FRR=0%, FAR=72.22%                         │   │
│  └───────────────────────┬─────────────────────────────┘   │
│                          │                                  │
│                    检测到候选?                               │
│                    /          \                             │
│                  否            是                            │
│                  ↓              ↓                           │
│              [拒绝]     ┌───────────────────────────────┐  │
│                        │  提取后缀音频 (40%~末尾)        │  │
│                        │  - 起始: 音频40%位置           │  │
│                        │  - 时长: 200ms ~ 800ms         │  │
│                        └───────────────┬───────────────┘  │
│                                        ↓                   │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  阶段2: MLP验证器                                    │   │
│  │  - 目标: 验证后缀是否为"真真"                        │   │
│  │  - 输入: MFCC特征 (13维 × 50帧)                     │   │
│  │  - 输出: 二分类概率                                  │   │
│  └───────────────────────┬─────────────────────────────┘   │
│                          │                                  │
│                    验证通过?                                │
│                    /          \                             │
│                  否            是                            │
│                  ↓              ↓                           │
│              [拒绝]         [唤醒]                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 阶段1：前缀检测器

复用V3 Zipformer模型，配置为高召回模式：

```python
class PrefixDetector:
    def __init__(self):
        self.spotter = sherpa_onnx.KeywordSpotter(
            tokens=tokens_path,
            encoder=encoder_path,
            decoder=decoder_path,
            joiner=joiner_path,
            keywords_file=keywords_path,
            provider='cpu'
        )
        self.threshold = 0.3  # 宽松阈值，确保高召回
```

**设计理念**：宁可多检测，不可漏检测。将误报过滤交给阶段2。

### 4.3 阶段2：MLP验证器

#### 4.3.1 网络结构

```python
class MLPVerifier(nn.Module):
    def __init__(self, input_dim=650, hidden_dims=[256, 128, 64]):
        super().__init__()
        self.network = nn.Sequential(
            nn.Linear(650, 256),    # 输入: 13 MFCC × 50帧 = 650
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(256, 128),
            nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(128, 64),
            nn.ReLU(),
            nn.Linear(64, 1),
            nn.Sigmoid()            # 输出: 二分类概率
        )
```

#### 4.3.2 特征提取

```python
def extract_features(audio, sr=16000):
    # 提取13维MFCC特征
    mfcc = librosa.feature.mfcc(
        y=audio, 
        sr=sr, 
        n_mfcc=13,
        n_fft=512,
        hop_length=160
    )
    # 调整到固定50帧
    if mfcc.shape[1] < 50:
        mfcc = np.pad(mfcc, ((0, 0), (0, 50 - mfcc.shape[1])))
    else:
        mfcc = mfcc[:, :50]
    return mfcc.flatten()  # 输出: 650维向量
```

### 4.4 后缀提取策略

```python
def extract_suffix(samples, sr, start_ratio=0.4, 
                   min_duration_ms=200, max_duration_ms=800):
    """
    从音频中提取后缀部分用于验证
    
    设计考量:
    - start_ratio=0.4: 跳过"你好"部分(约占40%)
    - min_duration_ms=200: 确保包含"真真"
    - max_duration_ms=800: 避免包含过多噪声
    """
    total_samples = len(samples)
    start_sample = int(total_samples * start_ratio)
    
    min_samples = int(sr * min_duration_ms / 1000)
    max_samples = int(sr * max_duration_ms / 1000)
    
    end_sample = min(start_sample + max_samples, total_samples)
    suffix = samples[start_sample:end_sample]
    
    # 确保最小长度
    if len(suffix) < min_samples:
        suffix = np.pad(suffix, (0, min_samples - len(suffix)))
    
    return suffix
```

## 6. 总结与展望

### 6.1 关键技术决策

1. **两阶段架构**：将检测和验证分离，各司其职
2. **高召回阶段1**：宁可误报，不可漏报
3. **精确验证阶段2**：专注于后缀特征验证
4. **轻量级MLP**：平衡精度与效率

### 6.2 可复用经验

1. **前缀问题的通用解法**：当目标词包含常见前缀时，多阶段检测是有效策略
2. **负样本设计**：硬负样本比通用负样本更重要
3. **过拟合预警**：FRR下降伴随FAR上升是过拟合信号
4. **Decoy策略局限**：不适用于前缀关键词场景

### 6.3 未来优化方向

1. **真实数据收集**：引入真人语音进一步提升泛化能力
2. **端到端训练**：将两阶段模型联合优化
3. **模型压缩**：进一步量化MLP验证器
4. **多关键词扩展**：支持更多唤醒词
